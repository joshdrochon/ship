W1-4 — how many type errors web/tsconfig.json hides by not extending the root config
====================================================================================

QUESTION
  Category 1's W1-4 records that web/tsconfig.json declares its compilerOptions from
  scratch instead of extending the repo root, and so silently drops three flags the root
  sets: noUncheckedIndexedAccess, noImplicitReturns, noFallthroughCasesInSwitch.
  The finding was never quantified. This file quantifies it.

METHOD
  web/tsconfig.json was NOT modified. A temporary config outside the repo tree extends it
  and adds only the three missing flags:

    {
      "extends": "<tree>/web/tsconfig.json",
      "compilerOptions": {
        "typeRoots": ["<tree>/web/node_modules/@types", "<tree>/node_modules/@types"],
        "noUncheckedIndexedAccess": true,
        "noImplicitReturns": true,
        "noFallthroughCasesInSwitch": true
      }
    }

  typeRoots must be pinned explicitly. TypeScript resolves automatic @types inclusion from
  the directory holding the config file being run, not from the config it extends, so a
  config outside the repo otherwise loses @types/node, @types/react and @types/react-dom
  and reports ~16 spurious TS2307/TS2304/TS2503/TS2580 errors. Pinning typeRoots removes
  all of them; the control run below is the proof.

  Run, per tree, from <tree>/web with that tree's own tsc:
    node_modules/.bin/tsc -p <temp-config> --noEmit --pretty false

  A control run of the UNMODIFIED web/tsconfig.json through the same temp-config mechanism
  is included so the delta is attributable to the three flags and nothing else.
